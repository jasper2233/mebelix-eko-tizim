# Frontend App — Routes, Hooks, Queries, Client va Konfiguratsiya

Bu hujjat MebeliX MES frontend ilovasining yadro qismini tavsiflaydi: build/tooling konfiguratsiyasi, ilova entry point'i, routing tuzilmasi, autentifikatsiya oqimi (auth flow), custom hook'lar, TanStack Query so'rovlari va OpenAPI'dan generatsiya qilinadigan API client.

**Texnologiyalar stack'i:**

| Qatlam | Texnologiya |
|---|---|
| Build tool | Vite + `@vitejs/plugin-react-swc` |
| UI framework | React 19 (StrictMode) |
| Routing | TanStack Router (file-based, code-generated) |
| Server state | TanStack Query (`QueryClient`, `queryOptions` factory'lar) |
| HTTP | Axios (cookie-based auth, `withCredentials`) |
| Styling | Tailwind CSS v4 (`@tailwindcss/vite`), shadcn/ui (new-york style) |
| Formalar | react-hook-form + zod (`zodResolver`) |
| Lint/format | Biome |
| API client | `@hey-api/openapi-ts` + `@hey-api/client-axios` |

## 2. Entry point va global fayllar

### `frontend/src/main.tsx`
Ilovaning eng muhim fayli — bootstrap + global HTTP xatti-harakati:

1. **API client sozlash**: `client.setConfig({ baseURL: API_BASE, withCredentials: true, timeout })` — `client` `./client/client.gen`dan import qilinadi (`./client` barreli uni eksport qilmaydi), `API_BASE` esa `utils.ts`dan (`VITE_API_URL ?? "http://localhost:8000"`). Global `OpenAPI` singletoni ham, global `axios.defaults` ham yo'q: sozlama klientning O'Z instansiyasiga qo'yiladi. Token JS xotirasida saqlanmaydi — autentifikatsiya to'liq HttpOnly cookie'lar orqali (`withCredentials` bilan avtomatik yuboriladi). Timeout: `VITE_API_TIMEOUT_MS` (default 30 000 ms).

2. **Silent refresh interceptor**: `client.instance.interceptors.response` 401 kelganda (agar so'rov `/login/` ostida BO'LMASA va hali retry qilinmagan bo'lsa — `/login/*` dagi 401 "sessiya eskirdi" emas, "kirish ma'lumoti noto'g'ri" degani: refresh urinilsa uning o'z xatosi asl xabarni bosib qolardi, beyjik skanerlagan operator "Beyjik topilmadi" o'rniga "Yangilash tokeni topilmadi" ni ko'rardi) `LoginService.refreshAccessToken()` ni chaqiradi — server yangi `access_token` cookie'sini o'rnatadi — so'ng asl so'rov qayta yuboriladi. Bir vaqtda kelgan parallel 401'lar bitta umumiy promise'ni kutadi (`refreshing ??= ...`, `finally`da tozalanadi): refresh muvaffaqiyatli bo'lsa hammasi qayta yuboriladi, yiqilsa hammasi shu xato bilan rad etiladi.

3. **401 fallback bu yerda EMAS**: `QueryClient` ham, uning `QueryCache`/`MutationCache` `onError` handler'i (`handleApiError`) ham `frontend/src/lib/queryClient.ts` ga ko'chgan (quyida alohida bo'lim); `main.tsx` faqat `queryClient` ni import qilib provider'ga uzatadi.

4. **Render**: `createRouter({ routeTree, defaultPendingComponent, defaultPendingMs: 200, defaultPendingMinMs: 500 })` (`routeTree` — generatsiya qilingan `routeTree.gen.ts`dan; route yuklanishi, `beforeLoad` auth so'rovi ham, 200 ms dan cho'zilsa `Common/BrandLoader` chiqadi va kamida 500 ms turadi — "lip" etib yo'qolmasin), `QueryClientProvider` + `RouterProvider` StrictMode ichida render qilinadi (Toaster bu yerda emas — `__root.tsx`dagi `AppToaster`da). `declare module "@tanstack/react-router"` orqali router type-registratsiyasi qilinadi (type-safe navigatsiya).

### `frontend/src/index.css`
Tailwind v4 uslubidagi global CSS: `@import "tailwindcss"`, `tw-animate-css`, `@fontsource-variable/archivo` (asosiy shrift — Archivo Variable). `@theme inline` bloki shadcn CSS o'zgaruvchilarini Tailwind token'lariga bog'laydi. **Tizim FAQAT light**: `dark` varianti umuman yo'q — shadcn komponentlaridan 23 ta `dark:` utility klass olib tashlangan, shu bilan birga `@custom-variant dark (&:where(.dark, .dark *))` qatori ham (endi hech narsaga qo'llanmaydi); `Toaster` `theme="light"` da qattiq belgilangan (`components/ui/sonner.tsx`) va tokenlarning birortasi ham dark uchun qayta belgilanmagan. `:root`da MebeliX brend palitrasi: navy `#2F496E` (primary), gold `#F0A52F` (ring/sidebar-primary), sidebar uchun to'q navy `#243a59` fon, kiosk ekranlar (tablo/terminal) uchun umumiy `--surface` `#f4f6f9` "qog'oz" foni; brend aksent token'lari — `--brand-gold` `#eaa83c`, `--brand-gold-deep` `#8a6420` (oq fondagi mayda yozuv uchun to'q oltin — `#b8862f` WCAG AA dan o'tmasdi), `--brand-navy-deep` `#16233a`. `@layer base`da border/outline default'lari va `button { cursor: pointer }`.

### `frontend/src/utils.ts`
API xatolarini toast'ga aylantirish yordamchilari:
- `errorDetail(err)` (ichki, eksport qilinmaydi) — server javob tanasidagi `detail`ni ajratadi: klient (`@hey-api/client-axios`) HAR QANDAY xatoni `AxiosError` qilib tashlaydi, ya'ni 4xx tanasi `err.response.data`da keladi (ilgari `ApiError.body` edi);
- `detailParts(err)` — **yagona xato zinapoyasi** (2026-09-04: Starlette/FastAPI'ning O'Z inglizcha `detail` satrlari — «Not Found», «Method Not Allowed», «Internal Server Error», «Not authenticated»… — `FASTAPI_DEFAULTS` orqali holat bo'yicha o'zbekcha matnga almashadi; MES'ning o'zi doim o'zbekcha `detail` beradi, `core/exceptions.py` standartlari ham o'zbekcha); qolgan ikkalasi shu funksiya ustiga qurilgan, shuning uchun har shart uchun BITTA o'zbekcha matn bor (ilgari `extractErrorMessage` o'z parallel zinapoyasini yuritardi va, masalan, `ECONNABORTED` uchun ikki xil matn chiqarardi). Qaytaradi: `{code, message, structured}`. Tartib: `ERR_NETWORK` → `TARMOQ` / "Tarmoq xatosi — internet aloqasini tekshiring"; `ECONNABORTED` → `KUTISH` / "So'rov vaqti tugadi — qayta urinib ko'ring"; FastAPI validatsiya massivi (`[{msg, loc}]` — inglizcha `msg` ko'rsatilmaydi) → `XATO` / "Kiritilgan ma'lumot noto'g'ri — tekshirib qayta yuboring" (massiv ham `object` bo'lgani uchun tuzilmali konvertdan OLDIN tekshiriladi); MES tuzilmali `{code, message}` konverti → o'sha kod va xabar (busiz toast'ga "[object Object]" tushardi); oddiy satrli `detail` → `XATO` / o'sha satr; tanada `detail` bo'lmasa (5xx, HTML sahifa, proxy xatosi) `XATO` va STATUS kodi bo'yicha ichki `holatXabari()`: 401/403 "Sessiya tugadi — qaytadan kiring", 404 "Ma'lumot topilmadi — sahifani yangilang", 413 "Fayl juda katta", 429 "Juda ko'p so'rov ...", 502/503/504 "Server yangilanmoqda ...", qolgan 5xx "Serverda xatolik ...", statussiz "Server javob bermadi — qayta urinib ko'ring", **qolgan hamma status** (tanasida `detail` yo'q 400/409 kabi) "So'rov bajarilmadi — qayta urinib ko'ring"; xato umuman `AxiosError` bo'lmasa (komponentdagi JS xatosi) "Xatolik yuz berdi — qayta urinib ko'ring". `structured` faqat serverning O'ZI `code` bergan holatda `true` — qolgan kodlar (`XATO`, `TARMOQ`, `KUTISH`) shu yerda to'qilgan yorliqlar;
- `extractErrorMessage(err: unknown)` — `detailParts` ustidagi bir qatorlik ko'rinish: `structured` bo'lsa `"E003: ..."`, aks holda faqat xabar (to'qilgan `XATO`/`TARMOQ` prefiksisiz); xabar bo'sh bo'lsa kodning o'zi. Toast, `ErrorComponent`, login formasidagi inline xato va terminal kontekst-xato sahifasi (`routes/terminal.tsx`) shuni oladi (axiosning inglizcha `err.message`i hech qachon ko'rsatilmaydi — tsexdagi operator "Request failed with status code 500" ni ko'rardi);
- `toastScanError(err)` — **terminal/skan xatosi toast'i** (2026-09-04): sarlavha = XABAR, kod kichik ikkinchi qatorda («Kod E008») — ilgari sarlavha `"E008: …"` edi, kod ishchiga hech narsa demasdi. `toastScanError` va `detailParts` **FAQAT terminal/skan oqimida ishlatiladi** (`routes/terminal.tsx`, `Terminal/TmoView`, `Terminal/UpakovkaView`; `detailParts` kodga qarab ovoz beradi: `routes/terminal.tsx` va `UpakovkaView` (E008 «allaqachon qadoqda» → ogohlantirish), `TmoView` faqat `toastScanError` (kodga qaramaydi)); admin sahifalari va dialoglari `onError: handleError` ni oladi. `detailMessage(err)` (kod oldinda bir qatorlik matn, faqat terminal kontekst-xato sahifasida edi) 2026-09-27 da olib tashlandi: MES xatosida `extractErrorMessage` bilan bir xil matn berardi, qolganida esa to'qilgan `XATO:`/`TARMOQ:` prefiksini qo'shardi;
- `handleError(err: unknown)` — TanStack Query `onError` uchun to'g'ridan-to'g'ri handler (`onError: handleError`) — `toast.error(extractErrorMessage(err))`; avvalgi curried varianti va `useCustomToast` wrapper'i olib tashlangan, hamma joyda sonner `toast.success/error` to'g'ridan-to'g'ri chaqiriladi;
- `API_BASE` — API bazasi (`import.meta.env.VITE_API_URL ?? "http://localhost:8000"`). Zamonaviy klientda `OpenAPI.BASE` kabi global yo'q, shuning uchun bazani bitta joydan oladigan hamma iste'molchi shu konstantaga tayanadi: `main.tsx` (`client.setConfig`), `hooks/useMesWs`, `lib/scxDir`, `components/Anketa/RoomPhotos.tsx`, `components/Orders/BazisPanel.tsx` (eskiz URL'i), `routes/3d.$token.tsx` (ochiq 3D eskizi), `_layout/agents.tsx` (agent exe havolasi), `_layout/orders/$orderId.tsx`;
- `getInitials(name)` — ismdan 2 harfli initsiallar (avatar uchun).

### Auth flow (login → cookie token → guard → silent refresh)

1. **Login**: `/login` formasida `useAuth().loginMutation` → `LoginService.loginAccessToken({ body: data })` (OAuth2 form-data: username/password — klient uni `urlSearchParamsBodySerializer` bilan `application/x-www-form-urlencoded` ga o'giradi). Server javobida `access_token` va `refresh_token` **HttpOnly cookie** sifatida o'rnatiladi — frontend token'ni hech qayerda saqlamaydi (`localStorage` yo'q). Muvaffaqiyatda `navigate({ to: "/" })`.
2. **Guard + rol-router**: har bir himoyalangan sahifaga kirishda `_layout.tsx` `beforeLoad`i `requireAuth()` (`lib/guards` — ichida `ensureQueryData(getCurrentUserQueryOptions())`, ya'ni birinchi so'rovdan keyin kesh) chaqiradi — cookie yaroqli bo'lsa rol tekshiriladi: `terminal`/operator rollar `/terminal` ga, `tablo` `/tablo` ga, faqat mahsulot omborchisi (`isWarehouseOnly`) o'z sahifalaridan (`OMBOR_YOLLARI` = `/warehouse`, `/sotuv`, `/settings`) tashqarida `/warehouse` ga yo'naltiriladi, qolganlar o'tadi; 401 bo'lsa `/login` ga redirect (boshqa xatolar `errorComponent`ga chiqadi). Ustiga o'n ikki sahifa o'z `beforeLoad` guard'idan o'tkazadi — o'n bittasi `lib/guards.requireAccess` bilan (predikatlar `lib/mes`dan): `/agents`, `/logs`, `/system-settings`, `/system-health` (`isAdmin`); `/clients`, `/employees`, `/reports` (`isManagement`); `/defects` (`isManager`); `/sotuv`, `/warehouse` (`isWarehouseStaff`); `/work-centers` (`isProductionStaff`); `/terminal` esa o'z rol tekshiruvidan. `/login` esa teskari tekshiradi: sessiya bor bo'lsa `/` ga qaytaradi.
3. **So'rovlar**: barcha API chaqiriqlar `withCredentials: true` bilan ketadi (`main.tsx`dagi `client.setConfig({ withCredentials: true })` — global `axios.defaults` emas, klientning O'Z instansiyasi), cookie avtomatik biriktiriladi.
4. **Silent refresh**: access token muddati tugab 401 kelsa, `main.tsx`dagi Axios interceptor `LoginService.refreshAccessToken()` orqali cookie'ni yangilab, asl so'rovni bir marta qayta yuboradi; parallel so'rovlar bitta umumiy refresh promise'ini kutadi.
5. **Fallback logout**: refresh ham 401 bersa (yoki `token_version` mismatch), `QueryCache`/`MutationCache` `onError`i cache'ni tozalab `/login` ga yo'naltiradi.
6. **Logout**: `useAuth().logout` → `LoginService.logout()` (server cookie'larni o'chiradi), `onSettled`da `queryClient.clear()` + `/login` ga navigate — server xato bersa ham lokal sessiya tozalanadi.
7. **Harakatsizlikdan chiqish**: `_layout.tsx` va `terminal.tsx` `useIdleLogout()` ni chaqiradi (TABLO chaqirmaydi, server ham unga chegara bermaydi). Chegara oshsa — `logout()`, ya'ni 6-band. `/login` sahifasi ochilganda `resetLastActivity()` eski vaqtni o'chiradi — aks holda qayta kirgan zahoti yana chiqarilardi. Server tomoni: refresh rad etiladi, worker ochiq smenani yopadi (03-backend-api.md `/login/refresh`, 04-backend-data.md §6).

Ikkalasi `queryOptions()` bilan e'lon qilingan (key/fn tiplashgan); `getCurrentUserQueryOptions` `queryFn`i `Promise<UserRead>` — xato yutilmaydi, 401 da so'rov THROW qiladi (`retry: false` factory'da — `useCurrentUser` `undefined` ko'radi, `lib/guards` esa 401 ni tutib `/login` ga chiqaradi). `staleTime` — 5 daqiqa: u FAQAT komponent obunachilarining (`useCurrentUser`, `tablo.tsx` observer'lari) mount/fokus refetch'larini to'xtatadi. Guard'lar (`beforeLoad`) esa `ensureQueryData` semantikasi tufayli keshdan o'qiydi — kesh bor bo'lsa qayta so'ramaydi va `staleTime`ga umuman qaramaydi. `getUsersQueryOptions` `queryFn`i sahifalab yig'adi: `PAGE_SIZE = 100` (`queries/mes.ts`dan import, backend `MAX_PAGE_SIZE`) bilan `readUsers({ query: { skip, limit } })` loop'da `count`ga yetguncha chaqiriladi (javob `AxiosResponse`, shuning uchun har chaqiruvda `.data` ochiladi) — 100 dan ortiq foydalanuvchi ham to'liq ko'rinadi (jadval client-side; foydalanuvchilar minglab bo'lsa server-side paginatsiyaga o'tish kerak bo'ladi). Unda ham `staleTime` 5 daqiqa: QueryClient'da default `staleTime` yo'q (`defaultOptions` ATAYLAB faqat `retry`/`refetchOnWindowFocus` beradi), shusiz har mount'da shu ketma-ket sahifa sikli boshidan qayta ishga tushardi.

`getUsersQueryOptions` ni birlashgan `/employees` sahifasi oddiy `useQuery` bilan ishlatadi (`/admin` faqat redirect, hech narsa so'ramaydi), `getCurrentUserQueryOptions` ni esa `useCurrentUser` va guard'lar. Odam/hisob mutatsiyalari (`People/PersonDialog`, `employees.tsx` dagi `TogglePerson`/`DeletePerson`) invalidatsiya uchun `["users"]` va `["employees"]` key'lariga tayanadi.

## 6. API Client (`frontend/src/client/`)

`@hey-api/openapi-ts` (0.99, `@hey-api/client-axios` runtime'i bilan) tomonidan TO'LIQ generatsiya qilinadi — bu katalogda qo'lda yoziladigan fayl yo'q. Tarkibi: `index.ts` (barrel), `sdk.gen.ts` (servis klasslari), `types.gen.ts` (domen tiplari), `client.gen.ts` (yagona klient instansiyasi) va ikkita runtime katalogi — `client/` (axios transporti) hamda `core/` (transportdan mustaqil yordamchilar).

**Chaqiruv shakli.** Ilgari (`legacy/axios`) metodlar tekis camelCase argument olardi va foydali yukni to'g'ridan-to'g'ri qaytarardi. Endi argument konvert ichida — `{ path, query, body }` — va uning kalitlari backend'dagi XOM nomlar (`order_id`, `qr_text`, `date_from`); javob esa `AxiosResponse`, ya'ni ma'lumot `.data` da:

```ts
const { data } = await OrdersService.readOrders({ query: { status, skip, limit: PAGE_SIZE } })
const { data } = await OrdersService.readOrder({ path: { order_id: orderId } })
```

Xato yo'li ham shu bilan o'zgargan: `ApiError` klassi endi yo'q — `throwOnError: true` tufayli klient har qanday xatoni `AxiosError` qilib tashlaydi, server tanasi esa `err.response.data` da (`utils.ts` dagi `errorDetail` shuni ajratadi).

### `frontend/src/client/index.ts`
Barrel eksport: `sdk.gen.ts` dagi 22 ta servis klassi + `Options` tipi va `types.gen.ts` dagi hamma request/response tiplari. Ilova bo'ylab import faqat `@/client` orqali. **Klient obyektining o'zi bu barrelda YO'Q** — uni `main.tsx` (sozlama + interceptor) va `_layout/reports.tsx` (Excel blob eksporti) alohida, `@/client/client.gen` dan import qiladi.

### `frontend/src/client/client.gen.ts`
Yagona klient instansiyasi: `createClient(createConfig({ throwOnError: true }))`. `sdk.gen.ts` ning har bir metodi shu `client` ga tushadi (chaqiruvda `options.client` berilmasa). `main.tsx` startup'da `client.setConfig({ baseURL, withCredentials, timeout })` qiladi va 401 interceptorini `client.instance` (ichkarida `axios.create()` bilan yaratilgan instansiya) ga ulaydi — global `axios` ga tegilmaydi.

### `frontend/src/client/client/` — axios transporti
- `client.gen.ts` — `createClient()`: axios instansiyasini yaratadi, `getConfig`/`setConfig`, HTTP metod funksiyalari (`get`/`post`/...), `buildUrl` va SSE klienti;
- `types.gen.ts` — transport tiplari: `Client` (`instance: AxiosInstance` maydoni bilan), `Config`, `ClientOptions` (`baseURL`, `throwOnError`), `RequestOptions`, `Options`, `TDataShape` va `RequestResult` — `throwOnError: true` da u oddiygina `Promise<AxiosResponse<T>>`;
- `utils.gen.ts` — `createConfig`, `mergeConfigs`, `mergeHeaders`, `buildUrl`, `setAuthParams`;
- `index.ts` — shu katalog va `core/` ning re-eksport barreli (`sdk.gen.ts` shundan import qiladi).

### `frontend/src/client/core/` — transportdan mustaqil yordamchilar
Sakkiz fayl, hammasi `*.gen.ts`: `auth.gen.ts` (`Auth` sxemasi va `getAuthToken` — MES'da ishlatilmaydi, autentifikatsiya cookie orqali), `bodySerializer.gen.ts` (`jsonBodySerializer`; `formDataBodySerializer` — `uploadRoomPhoto`/`uploadOrderProject`/`uploadOrderBazis`; `urlSearchParamsBodySerializer` — OAuth2 login formasi), `params.gen.ts` (`buildClientParams`), `pathSerializer.gen.ts` va `utils.gen.ts` (`{param}` path-interpolyatsiya, query serializatsiya, `getUrl`, `getValidRequestBody`), `queryKeySerializer.gen.ts`, `serverSentEvents.gen.ts` (SSE — MES jonli kanali WS'da, shuning uchun chaqirilmaydi) va `types.gen.ts` (`HttpMethod`, `Config`, `ClientMeta`).
